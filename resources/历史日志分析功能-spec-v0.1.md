# LAN Monitor — 日志分析功能 Spec

**Version: v0.1**

---

# 1. 功能目标

在当前 LAN Monitor 实时拓扑监控系统基础上，新增“历史日志分析”功能。

该功能基于系统保存的链路延迟日志文件：

```text
网络延迟日志.csv
```

对用户指定时间段内的链路延迟数据进行筛选、分析，并以交互式图表方式展示延迟变化趋势。

该功能的设计目标如下：

- 与现有实时拓扑监控功能解耦
- 不影响当前实时监控、worker、publisher、日志写入等已有功能
- 支持用户自行选择日志文件进行分析
- 支持用户选择时间范围与链路范围
- 支持导出图表为 PNG 图片
- 支持后续逐步扩展为更完整的历史分析模块

---

# 2. 功能定位

该功能属于**历史数据分析功能**，与当前系统中的**实时拓扑监控功能**是两个独立功能。

二者关系如下：

```text
实时拓扑监控
    ↘
      独立入口
        ↘
         历史日志分析
```

设计原则：

- 实时监控页负责当前网络状态展示
- 历史分析页负责历史日志回溯分析
- 二者页面分离
- 二者逻辑分离
- 二者共享同一套日志格式与配置体系
- 历史分析功能优先采用独立开发、后续再集成入口的方式推进

---

# 3. 页面入口与页面结构

## 3.1 页面入口

在当前拓扑页面中增加一个入口按钮，例如：

```text
历史日志分析
```

点击后：

- 打开一个新的浏览器标签页
- 进入独立的历史日志分析页面

说明：

- 该设计避免历史分析功能干扰当前实时拓扑页面
- 用户可同时保留实时监控页与历史分析页
- 新标签页有利于两类功能并行使用

## 3.2 页面结构

历史日志分析页面建议由以下区域组成：

### 3.2.1 顶部控制区

包含：

- CSV 文件选择控件
- 时间范围输入控件
- 链路视图切换控件
- 链路选择控件
- 分析按钮
- 导出图片按钮
- 提示信息区域

### 3.2.2 图表展示区

用于显示交互式延迟变化曲线图。

### 3.2.3 状态提示区

用于显示：

- 文件校验错误
- 时间范围错误
- 无数据提示
- 分析中状态
- 成功加载提示

# 4. 功能流程

整体流程如下：

```text
用户进入历史分析页
↓
选择 CSV 文件
↓
后端校验文件类型 / 大小 / 表头 / 内容格式
↓
用户输入开始时间和结束时间
↓
用户选择链路视图（普通链路 / 无线链路）
↓

↓
后端按时间范围和链路过滤数据
↓

↓
用户可导出 PNG 图片
```

# 5. 数据来源

## 5.1 输入数据来源

历史分析功能使用用户从浏览器界面中选择的 CSV 文件作为输入数据源。

用户选择方式：

- 在浏览器页面中选择本地 CSV 文件
- 文件上传到后端处理
- 后端完成校验和数据解析

说明：

- 第一阶段不直接读取服务器某固定路径下的文件
- 用户可选择默认日志目录中的文件，也可选择其他路径中的文件
- 浏览器端通常无法强制控制本地文件选择器默认打开目录，因此页面中可提示推荐目录，但不将“默认打开路径”作为强依赖能力

## 5.2 日志文件格式

当前系统日志文件格式为：

```text
时间,源IP,源设备,目标IP,目标设备,延迟(ms),状态
```

示例：

```text
2026-03-11 20:11:23,192.168.0.11,主机1,192.168.0.12,主机2,3.21,正常
```

说明：

- 时间字段用于横轴
- 延迟(ms) 字段用于纵轴
- 目标设备 / 目标IP 用于链路分组与筛选
- 状态字段在本阶段不用于绘图，仅作为原始日志组成部分保留

# 6. 文件选择与文件校验

## 6.1 文件选择方式

用户在浏览器界面选择需要分析的 CSV 文件。

实现方式：

- 使用前端文件选择控件
- 文件提交到后端进行处理
- 后端返回分析结果或错误信息

## 6.2 文件扩展名校验

当用户选择文件后，系统首先校验文件扩展名。

规则：

- 若文件扩展名不是 `.csv`
- 则提示用户文件选择错误
- 不允许继续分析

提示文案建议：

```text
文件选择错误，请重新选择正确的 CSV 日志文件。
```

## 6.3 文件大小校验

系统需对用户选择的文件大小进行校验。

规则：

- 文件大小不得超过允许上限
- 若超过上限，则拒绝分析并提示用户

提示文案建议：

```text
所选文件大小超过允许上限，请重新选择。
```

## 6.4 文件内容校验

即使文件扩展名正确，仍需校验文件内容是否为本系统生成的链路日志文件。

校验内容包括：

- 表头是否存在
- 表头顺序是否正确
- 必要字段是否齐全
- 表头内容是否与本系统日志格式一致

当前合法表头为：

```text
时间,源IP,源设备,目标IP,目标设备,延迟(ms),状态
```

若不符合，提示：

```text
文件选择错误，请重新选择正确的数据文件。
```

## 6.5 文件内容语义校验

除了表头，还应对内容做基本语义校验，例如：

- 是否至少存在一行数据
- 时间字段是否可解析
- 延迟字段是否为空或可转换为数值
- 目标设备字段是否与系统定义的链路设备集合相符

若校验失败，提示：

```text
文件内容格式错误，请重新选择正确的日志文件。
```

# 7. 时间范围分析规则

## 7.1 时间输入方式

第一阶段采用用户手动输入开始时间和结束时间。

格式固定为：

```text
YYYY-MM-DD HH:MM:SS
```

例如：

```text
2026-03-11 08:00:00
2026-03-11 12:00:00
```

## 7.2 时间校验规则

系统需校验：

- 开始时间不能为空
- 结束时间不能为空
- 开始时间格式必须合法
- 结束时间格式必须合法
- 开始时间必须早于结束时间

若校验失败，提示：

```text
时间范围输入错误，请检查后重新输入。
```

## 7.3 时间跨度限制

为了避免一次性分析过大数据范围，时间跨度需设置上限。

第一阶段规则：

- 单次分析的时间跨度不得超过 24 小时

若超出限制，提示：

```text
所选时间范围超过允许上限，请缩小时间范围后重试。
```

## 7.4 时间范围无数据提示

若：

- 文件合法
- 时间输入合法
- 时间跨度合法
- 但所选时间段内没有可用于绘图的数据

则提示：

```text
所选时间段内没有可用于绘图的数据。
```

# 8. 链路分组与视图设计

## 8.1 背景

当前系统共有 7 条链路数据。

其中：

- 6 条普通链路延迟较低
- `主机7-无线` 链路延迟明显高于其他 6 条链路

如果将 7 条链路全部放在同一纵轴下绘制，会导致普通链路波动细节被压缩，不利于观察。

因此需要对链路进行分组展示。

## 8.2 分组规则

第一阶段定义两类链路视图：

### 8.2.1 普通链路视图

包含：

- 主机1
- 主机2
- 主机3
- 主机4
- 主机5
- 主机6

### 8.2.2 无线链路视图

包含：

- 主机7-无线

## 8.3 视图切换方式

在历史分析页面中提供视图切换控件，例如：

- 有线链路
- 无线链路

用户在同一历史分析页中切换视图，不再额外打开新的页面。

---

# 9. 链路选择规则

## 9.1 用户可选一条或多条链路

用户可自由选择当前视图下需要显示的链路。

规则：

- 可以只选 1 条链路
- 可以同时选择多条链路
- 选中哪些，就绘制哪些

## 9.2 默认选择规则

### 9.2.1 普通链路视图默认选择

进入普通链路视图时：

- 默认显示该视图内全部普通链路

### 9.2.2 无线链路视图默认选择

进入无线链路视图时：

- 默认显示 `主机7-无线`

## 9.3 链路显示名称

前端展示时建议优先使用：

```text
目标设备
```

作为链路名称，而不是 IP。

例如：

- 主机1
- 主机2
- 主机7-无线

如有需要，也可在 tooltip 或图例中附带 IP 信息。

# 10. 图表绘制规则

## 10.1 图表类型

第一阶段采用：

- 交互式折线图

说明：

- 支持鼠标悬停查看数据
- 支持多条曲线同时展示
- 支持导出为图片
- 支持坐标轴自动调整

## 10.2 绘图内容

第一阶段只绘制：

- 延迟变化曲线

不绘制：

- 状态区间颜色
- 告警背景
- 状态切换标记
- 离线事件标记

用户通过纵轴数值和曲线走势自行判断延迟变化情况。

## 10.3 横轴规则

横轴使用：

```text
时间
```

根据当前筛选出的时间数据自动布局。

## 10.4 纵轴规则

纵轴使用：

```text
延迟(ms)
```

根据当前选中链路的有效数据自动计算显示范围。

规则：

- 自动根据有效延迟值调整纵轴范围
- 自动根据当前数据调整刻度
- 离线空值不参与纵轴极值计算

## 10.5 自动缩放原则

当前视图中的：

- 选中链路集合
- 选中时间段
- 有效数值范围

共同决定图表坐标轴显示范围。

系统不使用固定纵轴上限。

---

# 11. 离线数据处理规则

## 11.1 离线值来源

在当前系统日志中，若链路处于离线状态，则：

- `延迟(ms)` 字段为空字符串

## 11.2 绘图规则

离线数据不能显示为 0。

正确处理方式为：

- 将该点视为无有效数值点
- 在图中显示为空值
- 曲线在该位置断开
- 当后续再次出现有效延迟值时，从新的点重新开始绘制

## 11.3 设计目的

该规则可避免以下误导：

- 把离线误解为“0ms 延迟”
- 用连续线段误导用户认为链路始终连通
- 把离线状态伪装成低延迟状态

因此第一阶段必须坚持：

> 离线 = 空白断线，而不是 0 值。

# 12. 图表导出规则

## 12.1 导出格式

第一阶段仅支持导出为：

```text
PNG
```

## 12.2 导出内容

导出图片应反映用户当前看到的图表状态，包括：

- 当前视图分组
- 当前时间范围
- 当前选中的链路
- 当前图表显示内容

即：

> 用户看到什么，就导出什么。

## 12.3 导出触发方式

页面提供“导出图片”按钮。

点击后：

- 将当前图表导出为 PNG 文件
- 文件名可按时间或固定前缀生成

文件名建议示例：

```text
history-analysis-2026-03-11-120000.png
```

```text

↓
校验是否为 csv
↓
校验文件大小
↓
```

# 15. 前后端数据接口建议

## 15.1 请求参数建议

后端分析接口建议接收以下参数：

- 上传文件
- 开始时间
- 结束时间
- 视图类型
  - normal_group
  - wireless_group
- 选中链路列表

## 15.2 返回数据建议

后端返回数据建议包含：

- 是否成功
- 错误信息
- 当前时间范围
- 当前视图类型
- 当前链路列表
- 每条链路对应的时间序列数据

建议的数据结构形态：

```json
{
  "ok": true,
  "message": "",
  "view_type": "normal_group",
  "start_time": "2026-03-11 08:00:00",
  "end_time": "2026-03-11 12:00:00",
  "series": [
    {
      "device_name": "主机1",
      "target_ip": "192.168.0.11",
      "points": [
        ["2026-03-11 08:00:00", 3.2],
        ["2026-03-11 08:00:01", 3.4],
        ["2026-03-11 08:00:02", null],
        ["2026-03-11 08:00:03", 3.1]
      ]
    }
  ]
}
```

说明：

- `null` 表示离线或无有效数据
- 前端据此实现断线留白绘图

# 16. 配置项设计建议

为了使边界条件可配置，建议在 `config.json` 中新增独立配置组：

```json
{
  "history_analysis": {
    "enabled": true,
    "max_hours": 24,
    "max_file_size_mb": 50
  }
}
```

## 16.1 配置项说明

| 配置项           | 含义                               |
| ---------------- | ---------------------------------- |
| enabled          | 是否启用历史分析功能               |
| max_hours        | 单次分析允许的最大时间跨度         |
| max_file_size_mb | 历史分析功能允许加载的最大文件大小 |

## 16.2 为什么不直接复用 latency_log.max_file_size_mb

虽然当前日志系统中已有：

```text
latency_log.max_file_size_mb
```

但建议不要直接复用。

原因：

- `latency_log.max_file_size_mb` 表示运行期日志文件允许写到多大
- `history_analysis.max_file_size_mb` 表示分析页面允许加载多大的文件

两者语义不同，独立配置更清晰，也便于后续单独调整。

# 18. 与现有系统的集成边界

该功能在第一阶段应保持以下原则：

- 不修改现有实时拓扑渲染逻辑
- 不修改 worker 线程逻辑
- 不修改 publisher 推送逻辑
- 不修改当前日志写入逻辑
- 仅复用现有日志格式和配置机制
- 历史分析功能作为独立模块实现

说明：

第一阶段优先目标是：

> 在不破坏现有实时系统的前提下，新增一个可独立运行的历史日志分析模块。

# 19. 开发策略建议

建议采用两阶段策略：

## 19.1 第一阶段

先独立开发历史分析功能，包括：

- 页面
- 文件上传
- 后端解析
- 时间过滤
- 链路过滤
- 图表绘制
- 导出 PNG

## 19.2 第二阶段

再与主系统整合，包括：

- 在拓扑页增加入口按钮
- 与主系统静态资源整合
- 与主系统配置整合
- 保持版本兼容与行为一致

这样可以避免：

- 一开始就侵入主系统
- 影响现有实时功能
- 后期难以排查兼容问题

# 20. 当前版本的第一阶段目标总结

第一阶段实现目标如下：

- 新增独立的历史日志分析页面
- 用户通过浏览器选择 CSV 文件
- 后端处理并校验文件
- 支持最大文件大小限制
- 支持最大分析时间跨度限制
- 支持普通链路 / 无线链路视图切换
- 支持用户选择一条或多条链路绘图
- 普通链路视图默认全选
- 无线链路视图默认显示主机7-无线
- 仅绘制延迟变化曲线
- 离线数据断线留白
